# Audit keamanan, performa, dan UX HRjj

Tanggal: 27 November 2026. Baseline: `f08b551d9bcbfeaa620390b1b0a823dad49a478f`.

## Ringkasan dan batas pemeriksaan

Inventaris baseline: 186 file terlacak, 123 file di `src`, 8 Route Handlers, konfigurasi Next.js, CI, skema/migrasi, Server Actions, kontrol akses, kriptografi, penyimpanan dan komponen UI. Dilakukan penelusuran statis, pemeriksaan konektor layanan, pemindaian pola secret pada tree aktif, npm audit produksi, tes perilaku, tes browser dengan data dummy, dan tes MySQL di CI.

Ini bukan bukti aplikasi bebas kerentanan. Tidak dilakukan eksploitasi terhadap produksi, load test, pembacaan nilai secret Vercel, EXPLAIN terhadap data produksi, verifikasi grants aplikasi, pengukuran CWV/RUM pengguna nyata, atau pengujian semua kombinasi peran melalui sesi produksi. Pemindaian pola secret tidak sama dengan gitleaks seluruh riwayat Git.

Skor heuristik baseline (bukan hasil benchmark/pentest): keamanan 6/10, performa 6/10, responsivitas 8/10. Setelah perbaikan kode, target sementara 7.5/10, 7.5/10, 8.5/10; pekerjaan dashboard dan validasi operasional tetap diperlukan.

## Temuan yang masih perlu tindak lanjut

1. **Impor XLSX:** batas 1.5 MiB dan 500 baris diperiksa, tetapi XLSX adalah ZIP dan ExcelJS memuat workbook sebelum batas baris diterapkan. Perlu batas dekompresi/stream parser dan kuota impor per akun untuk menahan ZIP bomb. Jangan menganggap pemeriksaan MIME/header ukuran sudah cukup.
2. **Ekspor:** CSV mempunyai cancel iterator; XLSX/PDF masih membutuhkan pengujian pembatalan klien, pembatasan frekuensi, dan batas waktu untuk ekspor besar. Batch bukan snapshot transaksi: data yang diubah saat ekspor dapat membuat ringkasan dan isi berbeda.
3. **Data organisasi:** perubahan brand pada CV dapat mengubah brand karyawan sekaligus, tetapi hubungan lokasi/brand dan pembaruan organisasi yang bersamaan perlu validasi transaksi tambahan. Review sebagai perubahan bisnis terpisah.
4. **Deaktivasi manual karyawan:** validasi rentang tanggal keluar dan alasan keluar aktif perlu diperketat; jangan menjadwalkan tanggal keluar di masa depan dengan langsung menonaktifkan status.
5. **Dropdown surat/karyawan:** beberapa opsi master dan listLetterEmployees belum dibatasi. Ini bukan N+1, tetapi perlu pencarian server dengan pagination jika jumlah karyawan tumbuh besar. Hindari memuat semua nama ke Client Component.
6. **CSP:** baseline masih mengizinkan inline script/style untuk bootstrap Next.js/PPR. Ini mengurangi sebagian attack surface, tetapi bukan strict nonce CSP. Strict CSP harus diuji sebagai perubahan rendering tersendiri; nonce per request tidak cocok dengan PPR.
7. **Migrasi:** runner memperingatkan checksum migrasi yang berubah tetapi tidak langsung gagal. Pertimbangkan mode CI ketat, pemisahan pengguna migrasi, dan audit seluruh history secret dengan secret scanner.
8. **Runtime error:** sebagian Route Handler memakai guard berbasis redirect/error boundary untuk unauthorized; konsistensi JSON 401/403, korelasi error dan observability perlu diperluas tanpa membocorkan pesan SQL.

## Checklist dashboard dan rollout

### Aiven

- [ ] Pastikan database HRjj yang benar sebelum perintah migrasi; jangan tertukar dengan `db_jojogrp` milik aplikasi lain. Konfirmasi env HRjj, bukan hanya service URI default.
- [ ] Buat principal runtime terpisah dengan SELECT/INSERT/UPDATE/DELETE hanya untuk schema HRjj. Jangan gunakan avnadmin untuk runtime. Gunakan principal migrasi terpisah untuk DDL; jangan menjalankan seed di produksi.
- [ ] Unduh CA proyek; set **DB_SSL_MODE=verify-ca** dan **DB_SSL_CA** PEM di Vercel, uji preview, baru redeploy produksi. Cadangkan nilai lama untuk rollback. Kode mysql2 melakukan rejectUnauthorized:true pada mode ini.
- [ ] Batasi IP setelah seluruh egress HRjj, HRenter, CI migrasi, dan akses admin terpetakan. IP serverless biasa dinamis; gunakan fitur egress statis yang tersedia pada paket atau jalur jaringan lain. Jangan hanya menambahkan IP laptop lalu menghapus semua akses lainnya.
- [ ] Termination protection sudah aktif. Verifikasi retention backup dan lakukan restore drill terisolasi; backup tercatat bukan bukti restore berhasil.
- [ ] Ukur Threads_connected / max_connections / slow queries, p95 query dan kapasitas semua aplikasi. Pool 2 hanya limit per instance. MySQL bukan PostgreSQL: jangan memasang PgBouncer untuk MySQL.
- [ ] Saat window pemeliharaan, gunakan credential migrasi dan jalankan `npm run db:migrate` untuk **0017** setelah backup dan EXPLAIN. Jangan `db:seed`. Pantau metadata lock/DDL.

### Cloudflare

- [ ] R2 `hrjojo-private` tetap privat, r2.dev disabled, tanpa custom domain publik. Token hanya untuk bucket ini; credentials hanya server-side. Periksa custom domains dan kebijakan lifecycle sebelum menghapus dokumen.
- [ ] Jika Cloudflare diwajibkan sebagai proxy/WAF: tambahkan dan verifikasi domain milik organisasi pada Cloudflare serta Vercel terlebih dahulu. Saat ini frontend masih `.vercel.app`; jangan memblokirnya sebelum custom domain siap.
- [ ] SSL/TLS **Full (strict)**, bukan Flexible. Matikan fitur transformasi JavaScript seperti Rocket Loader pada aplikasi bila mengganggu hydration.
- [ ] WAF managed rules sesuai paket, pantau false positive. Terapkan rate rule POST `/login` (login memakai Server Action di halaman ini, bukan `/api/login`) dan `/api/employees/import`, dengan ambang awal yang ditinjau bersama HR. Proteksi aplikasi tetap diperlukan untuk POST Next-Action di halaman lain.
- [ ] Bypass cache bila cookie `hr_session` ada, untuk HTML autentikasi, `/api/*`, dan respons Set-Cookie. Jangan Cache Everything untuk HR. Pertahankan cache immutable hanya untuk aset `/_next/static/*` dan jangan mengabaikan query/Vary RSC.
- [ ] Jika trafik wajib melewati Cloudflare, kombinasikan custom hostname, Deployment Protection untuk URL deployment/alias, serta verifikasi origin header rahasia yang ditetapkan proxy dan diperiksa di origin/firewall. Host check atau percaya CF-Connecting-IP saja tidak cukup. Jangan mengandalkan IP Cloudflare bersama sebagai satu-satunya autentikasi origin.
- [ ] Vercel memperingatkan reverse proxy dapat mengurangi visibilitas firewall/bot protection. Gunakan konfigurasi verified proxy/visitor IP resmi dan uji login, Server Actions, streaming, preview PDF dan cache setelah aktivasi.

### Vercel

- [ ] Konfirmasi deployment baru benar-benar **sin1** dan build Node **24.x** (engines mengoverride setting proyek). Nilai setting proyek lama 26.x tidak otomatis menjadi bukti runtime baru salah.
- [ ] Production dan Preview memakai database/bucket/credentials terpisah atau akun read-only/fixture yang sesuai. Jangan menguji mutasi preview pada data produksi.
- [ ] Audit nama dan target env: DB__, AUTH_SECRET, FIELD__ dan R2_SECRET_ACCESS_KEY tidak boleh NEXT_PUBLIC_. Nilai env tidak dibaca dalam audit ini. Rotasi secret hanya jika dibutuhkan dan siapkan strategi key rotation agar data lama tetap terbaca.
- [ ] Deployment Protection untuk Preview dan URL deployment langsung; jangan menonaktifkan akses produksi sebelum jalur custom domain atau akun pengguna teruji.
- [ ] Tinjau Function concurrency, durasi, error alerts dan paket egress statis. Region dekat DB lebih berguna daripada menambah cache untuk data pribadi.
- [ ] Aktifkan pengukuran CWV/RUM yang sesuai izin privasi. Ukur LCP/INP/CLS dan p95 server sebelum menilai kenaikan performa.

### GitHub

- [ ] Ruleset `main`: wajib PR, pemeriksaan quality termasuk browser + integrasi MySQL, review sebelum merge, larangan force push/delete, dan tidak ada bypass luas.
- [ ] Enable secret scanning/push protection dan Dependabot sesuai dukungan paket. Audit seluruh history secara terpisah, bukan hanya tree saat ini.
- [ ] Pin actions ke full commit SHA dan gunakan pembaruan otomatis agar supply chain tetap terawat.
- [ ] Wajib CI sukses sebelum deploy/promotion produksi; integrasi Vercel dapat mulai membangun sebelum GitHub checks selesai. Jangan menganggap auto-deploy berarti CI gate sudah terpasang.
- [ ] Restrict GitHub App/Vercel access, pisahkan secrets lint/test (dummy) dan migrasi produksi. Workflow PR tidak boleh mendapat kredensial produksi.
